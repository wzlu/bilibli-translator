# md2zh:英文 Markdown 翻译 CLI 设计文档

- 日期:2026-10-12
- 状态:已确认(用户逐节审阅通过)
- 参考实现:`references/call_api.py`(Bilibili Index-Translate 免费翻译 API 调用示例)

## 1. 背景与目标

将英文 Markdown 文件翻译为中文,译文保存于原文件同目录,命名为 `*_zh.md`(如 `ABC.md → ABC_zh.md`)。工具形态为符合 unix-cli 规范的 Python 命令行程序,通过 Bilibili 免费翻译 API(OpenAI 兼容接口)完成翻译,全流程自动化、无人值守。

核心质量要求:**译文格式与原文严格一致**,包括代码块不译、frontmatter 结构、加黑 `**` 配对、链接格式、表格行列。

## 2. 需求清单

### 2.1 原始需求

1. 符合 unix-cli 规范;
2. 翻译英文 Markdown 文件或文件列表为中文;
   - `--filelist` 指定文件列表文本文件,每行一个 md 文件;
   - 无 `--filelist` 时,参数为单个文件名;
3. 译文保存于原文件同目录,`*_zh.md` 后缀;
4. 代码块内容不翻译;
5. 译文格式与原文一致,重点检查:frontmatter、加黑 `**` 位置、链接格式、表格格式。

### 2.2 澄清决策(与用户确认)

| 决策点 | 结论 |
|---|---|
| 无 `--filelist` 时的参数形态 | 单个文件名 |
| 依赖策略 | 允许第三方库(运行期 `requests`) |
| 已存在 `*_zh.md` | 默认跳过,`--force` 覆盖 |
| 多文件失败处理 | 继续处理,最后汇总,非零退出码 |
| 翻译策略 | 单次调用为主(≤阈值整文件流式),超长才分段兜底 |
| 术语表 | `--glossary` 指定文件;缺省自动加载 `~/.config/md2zh/glossary.json`(不存在视为无术语表);JSON 格式 `{"英文术语": "中文译法"}` |
| 格式校验失败 | 自动修复(重译),仍失败回退保留原文,全流程无人值守 |

## 3. 方案选型

- **方案 A(选定):结构化分段翻译的优化版**——单次调用为主、分段兜底。代码块占位符物理隔离,格式约束由提示词 + 块级校验 + 自动修复三重保障。
- 方案 B(整文件一次调用):长文件受 max_tokens/网关超时限制,格式无保障,不采用。
- 方案 C(行级流水线):请求次数多、术语不一致,过度设计,不采用。
- 术语一致性:单次调用天然一致;分段时用"前段上下文衔接";两遍术语自举因成本与复杂度按 YAGNI 不采用。

## 4. 项目结构与模块职责

```
D:\ops\bilibli-translator\
├── pyproject.toml            # 项目配置,命令行入口: md2zh
├── README.md
├── src/md2zh/
│   ├── __init__.py           # __version__
│   ├── cli.py                # 参数解析与入口(自定义用法错误退出码 64)
│   ├── api.py                # 翻译 API 调用(requests;提示词构建;流式;重试)
│   ├── markdown.py           # 块解析:frontmatter/代码块占位符保护、文本分段
│   ├── checks.py             # 块级格式校验:加黑配对、链接数、表格行列、frontmatter key 与 --- 标记
│   └── translator.py         # 编排:单文件翻译全流程(含自动修复循环)+ 文件列表处理
├── tests/                    # pytest 测试(API 用 mock,不依赖真实网络)
├── data/                     # 测试样例 markdown 文件(手工构造)
├── reports/                  # 测试报告
└── references/call_api.py    # 现有参考实现,保持不动
```

职责边界:

- `markdown.py`:纯文本变换,不涉及网络;
- `api.py`:HTTP 与提示词,不涉及文件;
- `checks.py`:纯函数校验,输入输出均为数据;
- `translator.py`:唯一编排者,持有翻译流程与文件 I/O;
- `cli.py`:只做参数解析、调用编排层、退出码映射。

## 5. CLI 接口

```
用法: md2zh FILE | md2zh --filelist LIST [选项]

选项:
  --filelist LIST   文件列表(每行一个 md 文件,支持空行与 # 注释)
  --force           覆盖已存在的 *_zh.md(默认跳过)
  --glossary FILE   术语表文件(JSON {"英文术语": "中文译法"});
                    缺省自动加载 ~/.config/md2zh/glossary.json,文件不存在则视为无术语表
  --api-base URL    翻译 API 地址(默认 https://index-translate.bilibili.com/v1)
  --model M         模型(默认 Index-Translate-35B-A3B)
  -h, --help        显示帮助并退出(退出码 0,输出到 stdout)
  --version         显示版本并退出(退出码 0,输出到 stdout)
```

接口约定(依据 unix-cli 规范):

- `FILE` 与 `--filelist` 互斥;两者皆无 → 用法错误(退出码 64)+ 简短用法提示到 stderr;
- stdout 只输出数据:每成功生成一个 `_zh.md`,输出一行该文件路径(可管道);进度、跳过提示、警告、汇总全部走 stderr;
- 错误消息 GNU 格式:`md2zh: 文件路径: 错误信息`;
- 文件列表路径相对当前工作目录解析。

## 6. 翻译管线

```
英文 md 文件
   │ 读取(UTF-8,含 BOM)
   ▼
块解析(markdown.py)
   │  ├─ frontmatter(--- 开头到 --- 结束)→ 独立翻译单元,仅译 value
   │  ├─ 围栏代码块 ```...``` → 占位符 @@@CODEBLOCK_n@@@(内容绝不发给 API)
   │  ├─ 行内代码 `x` → 占位符 @@@INLINE_n@@@(代码标识符不译)
   │  └─ 其余 → 可译文本
   ▼
分段决策
   │  ├─ 可译文本 ≤ 15000 字符 → 整文一次流式调用
   │  └─ 超长 → 按逻辑边界(段落/标题/表格/列表)切段,每段 ≤ 3000 字符,
   │        每段附前一段(原文+译文)尾部约 800 字符作上下文参考,保证术语延续
   ▼
翻译(api.py,requests 流式,temperature=0,enable_thinking=False)
   │  提示词 = 【源文】+【约束要求】+【硬性要求】术语表
   ▼
块级校验(checks.py)
   │  `**` 配对 / 链接数量 / 表格行列 / frontmatter key 集合与 --- 标记
   ▼
┌─ 校验失败? ──是──→ 自动修复:该块带【硬性要求】"上次翻译存在以下问题:…,请修正"
│        │            重新翻译(最多重试 2 次)
│        │                  │
│        │             仍失败?
│        │                  │是
│        │                  ▼
│        │             保守回退:该块保留原文(格式 100% 正确)+ stderr 警告
│        ▼
│     否
▼
重组:占位符还原 + frontmatter 按原文结构重建(--- 标记/key 顺序不变,仅 value 为译文)
   ▼
原子写 ABC_zh.md(同目录临时文件 + os.replace)→ stdout 输出该路径
```

### 6.1 格式约束提示词(每次请求携带)

1. 严格保留 markdown 语法结构;
2. 不得翻译或修改 `@@@...@@@` 占位符;
3. `**` 加黑标记必须成对出现、包裹对应的译文词语;
4. 链接 `[显示文本](url)`:只翻译显示文本,url 原样保留;
5. 表格保持行数与列数,分隔行保持;
6. frontmatter 的 key 保持不变,只翻译 value(复杂嵌套 YAML 不保证,由块级校验与回退原文兜底)。

### 6.2 自动修复与兜底

- 校验以块为单位,失败块重新翻译时附具体错误说明,最多重试 2 次;
- 重试仍失败 → 该块回退保留原文(格式天然正确),stderr 警告,流程继续;
- 发生回退的文件仍视为成功生成(退出码 0),警告便于事后发现。

## 7. 文件列表处理与错误处理

```
逐行读取 filelist:跳过空行与 # 注释行,路径相对当前工作目录
   │ 逐文件处理:
   ├─ 文件不存在/不可读、非 .md 后缀(不区分大小写)→ stderr 记录,继续下一个
   ├─ 已存在 *_zh.md 且无 --force → stderr 提示"跳过",继续
   ├─ API/网络错误(整文件失败)→ stderr 记录,继续
   └─ 成功 → stdout 输出该 _zh 文件路径
   ▼
结束时 stderr 汇总:"成功 N,跳过 M,失败 K"
```

- API 网络错误:自动重试 2 次;请求默认流式(规避参考脚本中提到的非流式 504 问题);
- 用户可见错误不打 Python 堆栈;
- 编码:输入 UTF-8(含 BOM),输出 UTF-8 无 BOM;
- 原子写:同目录临时文件 + `os.replace`,失败清理临时文件;
- SIGINT:Ctrl-C 时 stderr 简短提示并退出(130)。

## 8. 退出码

| 退出码 | 场景 |
|---|---|
| 0 | 全部成功(含全部跳过、含"回退保留原文"的文件) |
| 1 | 批量模式存在失败文件(汇总后) |
| 64 | 用法错误(EX_USAGE:缺参数、FILE 与 --filelist 冲突、未知选项),附简短用法提示到 stderr;需自定义 argparse 退出行为(默认是 2) |
| 66 | 输入文件不存在/无法读取(EX_NOINPUT,单文件模式) |
| 74 | 输出文件写入失败(EX_IOERR) |
| 75 | 翻译 API 临时不可用(EX_TEMPFAIL:网络错误/5xx,单文件模式且重试后仍失败) |
| 130 | 用户 Ctrl-C 中断(128+SIGINT) |

## 9. 术语表机制

- 格式:JSON `{"英文术语": "中文译法"}`,与 call_api.py 支持的术语表文件一致;
- 加载优先级:`--glossary` 指定文件 > 默认文件 `~/.config/md2zh/glossary.json`(不存在则无术语表,不算错误);
- 使用方式:解析为 `A→B` 对照,以【硬性要求】专名/术语对照附加到每段请求提示词。

## 11. 常量与默认值汇总

| 常量 | 值 |
|---|---|
| 单次调用阈值(可译文本) | 15000 字符 |
| 分段大小 | ≤ 3000 字符 |

## 12. 明确不做(YAGNI)

并发翻译、增量翻译、双语对照输出、目录递归扫描、`--strict` 校验即报错模式、图片翻译、`--serve` 代理模式(call_api.py 已有,不复制)。

## 13. 手工验证清单(实现完成后)

1. `md2zh --help` / `md2zh --version` 正常,退出码 0;
2. 翻译 `data/` 中样例文件(含 frontmatter/代码块/表格/链接/加黑),检查输出格式与代码块原样;
3. `--filelist` 批量处理,含坏行(不存在文件、非 md、空行、注释行),观察跳过与汇总;
4. 已存在 `_zh.md` 时默认跳过,`--force` 覆盖;
5. 自定义术语表文件与默认 `~/.config/md2zh/glossary.json` 各自生效;
6. 错误场景:不存在的单文件(66)、网络断开(75)、Ctrl-C(130)。
