# md2zh:链接 URL 占位符化与提示词稀疏化 设计文档

- 日期:2026-10-12
- 状态:已确认(用户批准设计;延续 v0.2.2 修复后的残余失败分析)
- 相关规格:`2026-10-12-context-placeholder-leak-design.md`(v0.2.2,上下文还原与隔离约束)、`2026-10-12-md2zh-translator-design.md`(保护管线与校验层)

## 1. 背景与目标

v0.2.2 修复「未知占位符」后,实测(opensre_system_prompt.md)残余两类块级失败:

1. **链接 url 与原文不一致**:模型改写 `[显示文本](url)` 中的 url——插件分析表明,官方插件的 URL 根本不在模型可见输入中(DOM href 属性承担保真),md2zh 翻译 markdown 源码,url 以字面文本暴露给模型;
2. **加黑标记计数不一致**:模型自行新增 `**`(0→4、2→4、4→6,重译间波动 4→6→8 不收敛)——假设:提示词逐项点名 `**` 令牌诱发模型过度加粗,且该文件本身是教模型格式的系统提示词。

目标:①URL 物理隔离(占位符化),根治链接类失败;②提示词稀疏化(去枚举)实验,降低加黑漂移失败率,以真实 API 对照基线验收。

## 2. 需求清单

1. 链接 URL 在发送 API 前替换为 `@@@URL_n@@@` 占位符,显示文本照常翻译,还原后与原 url 一致;
2. `FORMAT_CONSTRAINTS` 由 5 条并为 3 条,不注入 `**`/链接语法令牌字面量;
3. 校验层(checks.py)零改动:URL 占位符被既有占位符检查与链接检查自动覆盖;
4. 既有 123 项测试保持通过(受影响断言在 TDD 内更新),新增测试覆盖链接保护/还原;
5. 真实 API 手工实验:opensre_system_prompt.md 链接类失败消失、加黑失败块数不劣于基线,否则回退方向 2。

## 3. 方案选型

- **方向 1 方案 A(选定):仅 URL 占位符化**。`[显示文本](url)` 的 url 换 `@@@URL_n@@@`,显示文本照常翻译;还原时拼回。模型看不到 url 无从改动,是官方插件「DOM 承担 URL 保真」思想在源码翻译下的等价物。
- 方案 B(整链接占位符化):显示文本也隔离则无法翻译,否。
- 方案 C(校验放宽/修复说明具体化):治标,不消除根因,否。

- **方向 2 方案 A(选定):约束并条去枚举**。第 3/4 条(点名 `**`、链接语法)合并为一条不出现任何标记字面量的通用约束。改动最小、可一键回退。
- 方案 B(改修复循环 fix_notes 措辞):修复路径的点名问题,与方向 2 正交,本次不做(YAGNI,实验聚焦初译提示词)。

## 4. 详细设计

### 4.1 方向 1:链接保护(markdown.py)

`protect_code_blocks` 在 `_protect_fenced` → `_protect_inline` 之后增第三步 `_protect_links`,映射合并为 `{**fenced, **inline, **links}`:

```python
_LINK_URL_RE = re.compile(r"(\[[^\]\n]*\]\()([^)\n]*)(\))")

def _protect_links(text: str) -> tuple[str, dict[str, str]]:
    """链接 URL 替换为占位符(显示文本保留,照常翻译)。"""
    mapping: dict[str, str] = {}
    n = 0

    def repl(m: re.Match) -> str:
        nonlocal n
        ph = f"@@@URL_{n}@@@"
        mapping[ph] = m.group(2)
        n += 1
        return f"{m.group(1)}{ph}{m.group(3)}"

    return _LINK_URL_RE.sub(repl, text), mapping
```

要点:

- **顺序保证**:行内代码内的 `[x](y)` 已被 INLINE 占位符替换,不会被误保护;fenced 同理;
- 保护后链接形态 `[显示文本](@@@URL_n@@@)`,显示文本正常参与翻译;
- 占位符键 `@@@URL_n@@@` 与既有 CODEBLOCK/INLINE 命名一致,文档级还原 `restore_code_blocks` 遍历全映射自动覆盖,translator.py 零改动。

### 4.2 校验层零改动论证(checks.py)

- `check_placeholders` 的 `_PLACEHOLDER_RE = r"@@@[A-Z]+_\d+@@@"` 天然匹配 `URL_n`:模型改/丢 url 占位符 → 「占位符丢失/出现未知占位符」捕获;
- `check_links` 在保护形态下工作:原文/译文的 url 序列均为占位符序列,模型保持结构即相等;改写占位符即不等 → 「链接 url 与原文不一致」捕获。检查语义与现状等价;
- 表格/加黑检查不受影响。

### 4.3 方向 2:约束稀疏化(api.py)

`FORMAT_CONSTRAINTS` 替换为:

```python
FORMAT_CONSTRAINTS = [
    "严格保留 markdown 语法结构,全部格式标记与链接结构原样保留,仅翻译文字内容。",
    "不得翻译或修改 @@@...@@@ 占位符。",
    "表格保持行数与列数,分隔行保持。",
]
```

原第 3 条(点名 `**`)与第 4 条(点名链接语法)的意图并入第 1 条;第 1 条与表格条不变。`build_frontmatter_prompt` 的约束列表不动(frontmatter 无加黑/链接校验,范围最小化)。

### 4.4 兼容性与残余风险

- 保护形态变化:既有 markdown/checks/translator/api 测试中涉及链接的断言在 TDD 内更新;
- 上下文中 URL 以还原形态出现(与 v0.2.2 代码同机制):模型照抄上下文 url → 输出出现真实 url 而原文是占位符 → check_links 响亮失败 → 回退原文,由隔离硬约束压制,损害有界;
- 链接显示文本含 `]`/嵌套括号属既有启发式边界(CLAUDE.md 已知限制),不扩大不缩小;
- fix_notes 仍复述「加黑标记 ** 数量不一致」,修复路径的点名声不在本次实验范围(如实声明)。

### 4.5 范围界定

仅正文保护管线与初译提示词。frontmatter 提示词、修复循环、校验层、退出码、流约定、占位符编号方案、上下文机制均不动。
